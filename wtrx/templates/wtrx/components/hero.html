{% load i18n wagtailimages_tags wagtailcore_tags %} {% comment %} Shared hero component used by both HeroMixin (page-level) and HeroBlock (StreamField). Expects a `hero` dict (or object) with these keys/attributes: variant — "full" (HomePage's page-level hero only) or "banner" (every other HeroMixin page, and always for HeroBlock) headline — the heading text (str) copy — optional richtext value (rendered via |richtext or include_block) copy_is_block — True if copy should be rendered via include_block, False for |richtext image — optional CustomImage instance video — optional wagtailmedia Media instance (type="video") layout — "centered" (default) or "left". "full" variant only. banner_color — one of CALLOUT_COLOR_CHOICES. "banner" variant only. cta — optional HeroCTABlock stream value (0 or 1 items: signup/donate/announcement). "full" variant only — "banner" never renders one. variant switch: - "full": the original full-viewport hero — background video/image behind centered or left-aligned text, with a dark gradient scrim and room for a cta widget below the copy. See HeroMixin.hero_variant. - "banner": a compact rounded panel — solid/gradient color background (hero.banner_color, reusing CalloutBlock's 5-color system, see main.css's .wtr-hero-banner-{color}) on the left beside an image or video on the right, blended together with a matching-color fade (see .wtr-hero-banner-fade-{color}). No cta; much shorter than "full". Background video (either variant): autoplay/muted/loop/playsinline, no native controls — the pause/play pill (components/_hero_video_toggle.html) is the only playback control, custom-built instead of relying on browser-native video controls so it can sit as a small pill in the corner rather than a full control bar. Poster fallback chain (wagtailmedia thumbnail → hero.image rendition → none) lives in components/ _hero_background_video.html, shared by both variants since the logic is identical, just at different sizes (video_class/poster_spec). Page templates pass `hero` via the template context (set in get_context()). HeroBlock.get_context() builds this dict automatically (video is always None there — HeroBlock has no video field, only a page's own hero does). Height (full variant only): viewport height minus the site nav's height (h-16 = 4rem in header.html) when the nav is in normal flow; full viewport when the nav is transparent/overlaid (see HomePage.use_transparent_header — transparent_header is set on the page-level context and inherited here since hero.html is {% include %}'d without `only`). {% endcomment %} {% if hero.variant == "banner" %} {# ------------------------------------------------------------------ #} {# BANNER VARIANT — compact color panel beside an image/video #} {# ------------------------------------------------------------------ #} {% comment %} Flat px-4/pb-4 (16px), no top padding — matches Figma's Content Hero wrapper exactly (px-[16px] pb-[16px], no pt). The gap above the hero comes entirely from header.html's own py-6 bottom padding, same as Figma's Nav (py-[24px]) sitting directly above with no extra hero-side top padding of its own. This also applies when this same template renders as a mid-page HeroBlock inside page.body instead of the page-level HeroMixin hero: with no top padding here, the gap above a mid-page hero now comes purely from space-y-32's own 128px, consistent with every other block — previously py-8 stacked an extra 32px on top of that. {% endcomment %}
