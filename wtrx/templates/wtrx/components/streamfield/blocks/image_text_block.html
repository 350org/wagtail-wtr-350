{% load i18n wagtailcore_tags wagtailimages_tags %} {% comment %} Two-column split: a fixed-width image on the left, heading + richtext body on the right, vertically centered against each other (md:items-center). Single column on mobile (image, then heading/text, in that DOM order). Per Figma's The Great Power Shift (node 1:1234): a 1186px row, 128px gutter between the columns, an image column that does NOT grow, and a text column that takes the rest. The image is always force-cropped to a square (`aspect-square object-cover`, `rounded-lg`) — the same treatment ImageCardListBlock's and ImageGridBlock's images already use — rather than letterboxed via `object-contain` inside a fixed non-square box: there's no mechanism in this codebase for detecting a specific image's actual aspect ratio at render time, so the rounding rides along unconditionally with the crop, matching that precedent (AGENTS.md rule #35, ImageTextBlock's own docstring). No background is applied to the image or its wrapper. The image column's fixed width comes from the editor-controlled `size` field (IMAGE_TEXT_SIZE_CHOICES) — "Default" is 378px, matching Figma. Type scale follows Figma's proportions one notch down: 40px heading (lg:text-40, 64px in Figma), 24px body, 1.2 leading on both. See the type scale note in AGENTS.md. Heading and body used to be two fields (and a flex gap-8 owned the 32px between them); now they're one richtext field (`content`) and that spacing comes from Typography's own heading margin instead — see ImageTextBlock's docstring for the field history. Full-bleed-ish width: same w-full-outer / max-w-inner two-tier pattern as callout_block.html/image_card_list_block.html — see callout_block.html's comment for why a bare `50% - 50vw` bleed isn't used instead. No vertical padding on the w-full-outer wrapper — the 128px gap between body blocks comes from the page templates' space-y-32 on the block loop. {% endcomment %}
