{% load i18n wagtailcore_tags wagtailimages_tags %} {% comment %} Two-column split: a fixed-width graphic on the left, heading + richtext body on the right, both top-aligned (md:items-start). Single column on mobile (image, then heading/text, in that DOM order). Per Figma's The Great Power Shift (node 1:1234): a 1186px row, 128px gutter between the columns, a 378px image column that does NOT grow, and a text column that takes the rest. The image is object-contain inside a fixed 378x299 box, not object-cover in a stretched aspect-[4/3] one — this block's image is a wordmark/graphic (contrast ImageCardListBlock, which force-fills a photo to match a taller cards column), and cropping or upscaling a logo to fill half the row is exactly the wrong treatment. `contain` also means a graphic with a different aspect ratio than 378x299 letterboxes inside the box rather than distorting. Type scale follows Figma's proportions one notch down: 40px heading (lg:text-40, 64px in Figma), 24px body, 1.2 leading on both. See the type scale note in AGENTS.md. Heading and body used to be two fields (and a flex gap-8 owned the 32px between them); now they're one richtext field (`content`) and that spacing comes from Typography's own heading margin instead — see ImageTextBlock's docstring for the field history. Full-bleed-ish width: same w-full-outer / max-w-inner two-tier pattern as callout_block.html/image_card_list_block.html — see callout_block.html's comment for why a bare `50% - 50vw` bleed isn't used instead. No vertical padding on the w-full-outer wrapper — the 128px gap between body blocks comes from the page templates' space-y-32 on the block loop. {% endcomment %}
