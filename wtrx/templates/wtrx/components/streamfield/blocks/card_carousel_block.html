The buttons are a progressive-enhancement layer on top of the track's own native scroll/swipe, which works with JS disabled too. data-carousel is scoped per block instance (not a single page-wide guard like _actionkit_form.html's) since a page can have more than one carousel, each needing its own track/button wiring. Edge fade: a white-to-transparent gradient (.wtr-card-carousel-fade, see main.css) is pinned over the track's right edge, not baked into any one card — the card that's actually half-cut-off there changes as the user scrolls, so a fixed overlay at the edge (content scrolls underneath it) is what actually tracks "whichever card is currently half offscreen", rather than a per-card gradient that would only be correct for one scroll position. It's hidden (via the same updateArrows() that toggles the arrow buttons) once nextBtn is disabled — at the end of the scroll the last card is fully visible, not cut off, so nothing there should be faded. py-12 on the root: this block is special-cased out of the shared `mx-auto max-w-5xl px-4 sm:px-6 lg:px-8 py-8` wrapper every other non-"section" block gets from content_page.html/home_page.html (see the Width note below for why), so it doesn't inherit that wrapper's py-8 either — this replaces it directly, padding rather than margin so it can't collapse with an adjacent block's own margin at the top edge. Equal card heights: the track's own flex row already stretches each [data-carousel-item] wrapper to match the tallest one (align-items' default is stretch), but that stretch only affects the wrapper's own box — .wtr-card inside it (components/card.html) is a plain block child, not itself a flex item, so it doesn't inherit that stretched height and was sitting at its own natural (shorter) height inside a taller wrapper. Making the wrapper `flex` too promotes .wtr-card to a flex item of it, picking up the same default stretch and filling the wrapper's full (already-stretched-to-tallest) height. Width: card_carousel is special-cased in content_page.html/home_page.html (alongside "section") to skip the shared `mx-auto max-w-5xl px-4 sm:px-6 lg:px-8` wrapper every other block gets, so this template owns its own width instead — `mx-auto max-w-[1500px]` on the row itself, wider than that shared 1024px cap (per design) and no longer bound by it, with its own matching pl-4/6/8 so the text column's left edge still lines up with every other block at any viewport up to 1500px (both are just "edge of viewport" until 1500px, where this one alone stops growing and centers). An earlier version kept the shared wrapper and used the `50% - 50vw` bleed trick to break just the cards column out to the true viewport edge. That caused real horizontal page overflow: 100vw is the *layout* viewport width, which includes the scrollbar's own width, so the bleed overshot the visible area by the scrollbar's width on any OS/browser that reserves space for one (most non-macOS-overlay setups) — a well-known gotcha with that technique. Owning a capped, self-contained width instead of computing a bleed relative to the true viewport sidesteps that entirely, and also gives the ~1500px cap directly, with no extra work. No pr-4/6/8 on the row itself — the cards column intentionally has no padding there, so cards still visually run to (and get cut off at) this container's own right edge, same look as before, just capped at 1500px instead of the true viewport edge. The text column carries its own pr-4/sm:pr-6 instead (reset to lg:pr-0), scoped to mobile/tablet only — below lg: the columns stack (flex-col) and share the row's full width, so without it the right-aligned text/button would run flush to the row's own right edge same as the cards; at lg:+ the column's width is already capped well short of that edge by lg:w-1/3, so no extra padding is needed there. {% endcomment %}
