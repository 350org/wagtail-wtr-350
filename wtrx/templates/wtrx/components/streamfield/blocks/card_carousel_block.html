{% load i18n wagtailcore_tags %} {% comment %} Heading + rich text (+ optional CTA button) sit in a fixed left column; cards scroll horizontally in the right column via native CSS scroll-snap (see main.css's .wtr-card-carousel-track), with JS-driven prev/next arrow buttons that scroll by one card width at a time and disable themselves at the start/end — no wraparound. The buttons are a progressive-enhancement layer on top of the track's own native scroll/swipe, which works with JS disabled too. data-carousel is scoped per block instance (not a single page-wide guard like _actionkit_form.html's) since a page can have more than one carousel, each needing its own track/button wiring. Edge fade: a white-to-transparent gradient (.wtr-card-carousel-fade, see main.css) is pinned over the track's right edge, not baked into any one card — the card that's actually half-cut-off there changes as the user scrolls, so a fixed overlay at the edge (content scrolls underneath it) is what actually tracks "whichever card is currently half offscreen", rather than a per-card gradient that would only be correct for one scroll position. It's hidden (via the same updateArrows() that toggles the arrow buttons) once nextBtn is disabled — at the end of the scroll the last card is fully visible, not cut off, so nothing there should be faded. No vertical padding on the root: this block is special-cased out of the shared `mx-auto max-w-[800px] px-4 sm:px-6 lg:px-8` wrapper every other non-"section" block gets from content_page.html/home_page.html (see the Width note below for why), so it doesn't inherit that wrapper's horizontal gutters either — it owns its own pl-4/6/8 directly. The gap between body blocks comes from the page templates' space-y-* on the block loop, not from padding here. The arrow row's -mb-8 is a correction rather than styling: unlike every other block, this one ends in a 60px arrow row (the 44px buttons plus their mt-4) that is chrome, not content. The block loop's gap then starts below *that*, so the space under the last card read as 156px against the 96px every neighbouring block gets. Pulling 32px back lands it at 124px — deliberately not the full 60px, since the buttons still need room beneath them. The negative margin goes on the arrow row, NOT on this root. Tailwind v4 applies the loop's spacing as `margin-block-end` on the root, and the `:where()` in its selector contributes no specificity — so a `-mb-8` on the root does not *reduce* that gap, it replaces it outright (96px → -32px, dropping the next block on top of the arrows). On the arrow row it instead ends the block's own box 32px higher, letting the buttons overhang it, and the loop's gap is measured from there — so this stays correct on the home page's larger space-y-32 as well, which a hardcoded root margin would not. Equal card heights: the track's own flex row already stretches each [data-carousel-item] wrapper to match the tallest one (align-items' default is stretch), but that stretch only affects the wrapper's own box — .wtr-card inside it (components/card.html) is a plain block child, not itself a flex item, so it doesn't inherit that stretched height and was sitting at its own natural (shorter) height inside a taller wrapper. Making the wrapper `flex` too promotes .wtr-card to a flex item of it, picking up the same default stretch and filling the wrapper's full (already-stretched-to-tallest) height. Width: card_carousel is special-cased in content_page.html/home_page.html (alongside "section") to skip the shared `mx-auto max-w-5xl px-4 sm:px-6 lg:px-8` wrapper every other block gets, so this template owns its own width instead — `mx-auto max-w-[1500px]` on the row itself, wider than that shared 1024px cap (per design) and no longer bound by it, with its own matching pl-4/6/8 so the text column's left edge still lines up with every other block at any viewport up to 1500px (both are just "edge of viewport" until 1500px, where this one alone stops growing and centers). An earlier version kept the shared wrapper and used the `50% - 50vw` bleed trick to break just the cards column out to the true viewport edge. That caused real horizontal page overflow: 100vw is the *layout* viewport width, which includes the scrollbar's own width, so the bleed overshot the visible area by the scrollbar's width on any OS/browser that reserves space for one (most non-macOS-overlay setups) — a well-known gotcha with that technique. Owning a capped, self-contained width instead of computing a bleed relative to the true viewport sidesteps that entirely, and also gives the ~1500px cap directly, with no extra work. No pr-4/6/8 on the row itself — the cards column intentionally has no padding there, so cards still visually run to (and get cut off at) this container's own right edge, same look as before, just capped at 1500px instead of the true viewport edge. The text column carries its own pr-4/sm:pr-6 instead (reset to md:pr-0), scoped to mobile only — below md: the columns stack (flex-col) and share the row's full width, so without it the right-aligned text/button would run flush to the row's own right edge same as the cards; at md:+ the column's width is already capped well short of that edge by md:max-w-[400px], so no extra padding is needed there. md:, not lg:, is the row-split breakpoint: side-by-side now holds through tablet, and only phones (below md:) stack — narrower than the 520/583px column this used to size against, so tablet has plenty of room for the row without wrapping oddly. {% endcomment %}
