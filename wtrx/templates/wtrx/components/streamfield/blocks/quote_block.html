{% load i18n wagtailimages_tags wagtailcore_tags %} {% comment %} Image at ~80% width from sm: up, aligned per value.alignment (image-left/image-right) with a ~20% gutter on the other side for the text to spill into. Below sm: the image is full-width instead — see the vertical-containment note below for why. Text sits directly on top (no card/box) on the OPPOSITE side from the image — each line gets a tight white "highlighter" background via .wtr-quote-highlight (box-decoration-break: clone, see main.css) rather than one padded rectangle behind the whole paragraph. Spill: the text overlay is a SIBLING of the image (positioned relative to the outer, full-width wrapper, not clipped by the image's own overflow-hidden), so it's meant to spill horizontally past the image's edge into the empty ~20% gutter on the side opposite the image, at every breakpoint — no separate stacked-below layout for mobile; the overlay effect itself stays on. It must NOT spill vertically though — bottom-4/8 insets it up from the bottom edge (not translated past it), and since the image is the only normal-flow content, the outer wrapper's height equals the image's height, so "bottom" here is anchored to the image's own bottom edge. Staying vertically contained across every screen size, with a fixed aspect-video ratio and no layout fallback, rests on two things together: .wtr-quote-highlight's font-size clamp()ing down on narrow viewports (see main.css), and the image itself going full-width (not 80%) below sm:. Both matter — a long quote + CTA button easily needs more height than an 80%-width phone-screen image has, even at the font clamp's floor size, so trading the horizontal "spill into the gutter" effect (moot on a phone anyway — there's no gutter narrow screens can spare) for the ~25% taller image (1/0.8 wider = 1/0.8 taller, aspect ratio fixed) buys back real headroom rather than just shrinking text further. flex + items-end/items-start (not text-align + margin-left/right:auto) for the alignment — a max-width-only block's width stays "auto" under the hood, which forces any auto margin to resolve to 0 before max-width clamps it (CSS2.1 10.3.3's over-constrained-auto-margins rule). Flexbox's own alignment algorithm doesn't have that gotcha. {% endcomment %} {% comment %} Width matches image_block.html exactly — max-w-[1500px] with the shared px-4 sm:px-6 lg:px-8 gutter — and "quote" is in the page templates' full-bleed list so this block owns its own width rather than inheriting the body column's max-w-5xl. The two blocks are frequently stacked and both are a single full-width piece of media, so a quote at 1024px against an image at 1500px read as a mistake. Note this caps the *outer* wrapper. The image inside is still sm:w-4/5 of that, and the text overlay still spills into the remaining ~20% gutter — the proportions of the composition are unchanged, it is just measured against a wider container now. {% endcomment %}
