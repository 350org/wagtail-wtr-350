{% load i18n wagtailcore_tags %} {% comment %} Shared ActionKit form renderer, used by signup_actionkit_block.html's standalone panel (SignupActionKitBlock) and by signup_actionkit_hero_block.html's hero CTA strip (HeroSignupActionKitBlock, HeroCTABlock's "signup" choice). Both block classes share their form-fetching/caching/panel-tone logic via SignupActionKitFormMixin. Expects from context: form_html, actionkit_base_url, short_form_id (set by SignupActionKitFormMixin.get_context()), and exactly one of the layout flags `inline` / `stacked`, passed explicitly by the including template. Also expects thank-you content, in one of two forms depending on the caller: `success_message` (a SuccessMessageBlock StreamValue, set by SignupActionKitFormMixin.get_context() — rendered via include_block) or `success_text` (a plain string, set by resolved_footer_newsletter_signup() for the footer's newsletter box, which has no StreamField content editor of its own — rendered as-is). A caller sets at most one; either enables the thank-you swap below. inline=True → .wtr-actionkit-embed-inline: fields wrap across one row with the submit button on the same line. For the hero CTA strip, which is wide and short. stacked=True → .wtr-actionkit-embed-stacked: full-width fields in a single column with a full-width submit below. For the panel's 370px form column (Figma node 1:1245). Neither flag renders ActionKit's own unstyled vertical stack; both are full restyles of the same fetched markup. See main.css for each. `panel_tone` (from SignupActionKitFormMixin.get_context(), via SignupActionKitFormMixin.PANEL_TONES) adds a .wtr-ak-on-{tone} modifier for the panel fills the stacked chrome collides with — a dark panel behind the dark fine-print box, a blue panel behind the blue submit button, a light panel behind light-on-color labels. Applied only alongside stacked=True: the inline variant sits in the hero's own overlay, whose color this block's `background` field has no say over. {% endcomment %} {% if form_html %} {% comment %} The block picker preview renders a static stand-in form (see SignupActionKitFormMixin.PREVIEW_FORM_HTML), which needs neither jQuery nor the submit/UTM wiring below -- and must not pull either from a third party. {% endcomment %} {% if not is_block_preview %} {% endif %} {% comment %} Neither variant carries a top margin. The inline one is the hero CTA, and the hero already sets the gap between its headline and this widget (20px, per Figma's Content frame) on the wrapper it renders around the block; stacking another 32px inside pushed the form to 52px below the headline. HeroSignupActionKitBlock has no heading/description field of its own, so there is nothing else for that gap to space from. The stacked one used to carry mt-8, which was always dead space: its only caller is signup_actionkit_block.html's standalone panel, where this embed is the sole child of its own column and has nothing above it to be spaced from. All it did was push the form 32px below the panel's own p-16, which reads as a gap at the top of the panel — most visible when the form is short (the home page's two-field form) and the copy column beside it is shorter still. {% endcomment %}
